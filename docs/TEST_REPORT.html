What the automated suite checks

  • Correct retail check digits for EAN-13, EAN-8 and UPC-A; rejection of incorrect supplied checksums, unsupported characters, control characters and empty values.
  • Independent encode/decode round trips for all six symbologies, including Turkish UTF-8 QR content; blank raster rejection; QR quiet zones and minimum module sizes.
  • Exact 8-dot/mm conversion, label bounds, template schema, gap constraints, immutable cloning, and Turkish field substitution.
  • Exact EPL2 header/payload/trailer bytes; native Code 128 syntax; calibration and configuration commands; pixel polarity, bit order, white padding, embedded LF, NUL and 0xff; quantity, speed, darkness and raster-size checks.
  • Short-write offsets, zero/impossible write rejection and cancellation before the next chunk. These test the shared byte pump, not the Windows DLL itself.
  • SQLite CRUD, integer-cent prices, image bytes, persistence, duplicate SKU errors, upsert identity, validation before import, transaction rollback after a database failure, print history and a WAL-consistent backup.
  • CSV/XLSX Turkish text, multiline/quoted CSV, decimal separators, leading zeros, Base64 images, malformed CSV rejection, Excel formula rejection, explicit Excel text export, numeric price precision and both UI resource languages.

Limits relevant to release decisions

The application can inspect installed queues and the status reported by their drivers. It does not query USB hardware directly or receive EPL acknowledgements from the printer. A disconnected legacy USB printer may still have an apparently ready queue. The UI therefore reports “submitted”, never “physically printed”.

Font metrics, WPF templates, actual driver capabilities, runtime native extraction, firmware interpretation and thermal output need target-Windows testing. The included self-test produces local PNGs and a result file without accessing any printer. The hardware script submits bytes only on an explicit -Print request and records physicalPrintVerified: false until an operator observes output.

The original TLP 2844 is discontinued. No current official Windows 11 certification is asserted for the user's unknown legacy driver. The release includes neither a driver installer nor firmware. The app is unsigned. The build artifacts and source have SHA-256 digests in the delivered checksum files.

Nine added tests cover explicit English on a Turkish thread, live indexer and revision notifications, main-assembly English resource inclusion, complete key parity, independent catalogs, supported code normalization and saved-language persistence without changing products. The exact failure on the user's Windows installation was not directly reproduced. This patch removes the dependence on ambient Windows UI culture and satellite-resource deployment and implements immediate UI refresh.

0.1.2 workflow and recovery regression checks

21 added portable test cases cover product-token detection, static labels without catalog data, product snapshots, WAL-consistent restore, preservation of safety backups, rejection of foreign/corrupt databases and invalid drafts, rollback after a database constraint failure, seven-backup retention and atomic session validation. All 102 portable tests pass. The Windows-only smoke test adds actual WPF static-label rendering, missing-product guards, product preview and layout at smaller logical window sizes. It is supplied but NOT RUN on this Linux host. Window-size checks are not a substitute for real 125%/150% Windows display-scale acceptance.

Driver cancellation remains through the Windows queue; this release does not claim to cancel a synchronous XPS Write operation from the app's RAW cancellation button.
